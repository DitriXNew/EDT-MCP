# stop_profiling

Stop BSL performance measurement and optionally name the newly collected measurement.

## Parameters
| Parameter | Required | Type | Description |
| --- | --- | --- | --- |
| applicationId | yes | string | Application id of the running debug session (required) |
| name | — | string | Optional measurement name; a new UUID must arrive within 5 seconds. |

## Guide
Stop a task-owned profiling window for the required `applicationId`. Returns JSON with `active`, `stopped`, application id and an explanatory message. Repeating a stop on an inactive id is a safe no-op and never toggles profiling on.

## Name and identify the result

`{"applicationId":"<debug-session-id>","name":"After optimization"}` optionally assigns a unique name. Names must be valid directory names (up to 120 characters, no separators, reserved device names or trailing dots/spaces): EDT uses names as store folders. Existing names are refused before stopping.

Before toggling off, the tool captures loaded UUIDs. On the worker thread it waits at most five seconds for a new UUID. When exactly one arrives, it optionally calls EDT's `setResultName` on the workbench UI thread (or the worker when no workbench display exists), then re-reads the UUID and returns the observed `measurementId` and `name`. EDT saves before notifying listeners: a listener exception after an observed rename still returns success, with a note that the profiling view may need a refresh. An unobserved rename is an error even when profiling stopped. Existing measurements are never renamed. If multiple measurements arrive or none arrives in time, the response plainly says no measurement was named; check `get_profiling_results` with `mode=list` later. A late name collision is reported without renaming.

An inactive id or an ended debug target has no newly observed identity and does not apply `name`. An invalid supplied name is rejected even for an inactive id. If the debug target has ended, tracked profiling state is cleared. Use `debug_status`/`get_applications` to resolve a running application before starting a new window.

## Read the measurement

Retain the returned UUID and call `get_profiling_results` with that `measurementId` for a Markdown summary. Use `mode=lines` with filters and `limit`/`offset` for line details, or `mode=compare` with explicit before/after UUIDs. `applicationId` alone never selects stored results. Preserve attribution: no UUID means collection remains unconfirmed, not that the latest older result belongs to this run.
